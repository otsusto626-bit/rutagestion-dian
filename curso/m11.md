# intro

Un **algoritmo de trading** es un programa que aplica reglas para decidir y ejecutar operaciones. Automatizar tiene ventajas claras: elimina las emociones de la ejecución, permite probar ideas en miles de días de datos en segundos y vigilar muchos mercados a la vez. También tiene riesgos nuevos: errores de programación que pierden dinero en minutos, sistemas que fallan sin que nadie lo note y la tentación de sobreajustar con más facilidad que nunca.

Este módulo es opcional y requiere aprender algo de programación. Usa **Python**, el lenguaje más usado en finanzas cuantitativas. Verás código completo y probado para descargar datos, calcular indicadores, hacer un backtest con costos, reproducir las simulaciones de Monte Carlo del Módulo 06 y enviar órdenes a una cuenta de práctica por API. La última lección explica qué puede y qué no puede hacer el aprendizaje automático en los mercados.

# lección: Qué es el trading algorítmico y qué necesitas

## Los componentes de un sistema automatizado

Todo sistema algorítmico, desde el más simple hasta el de un fondo, tiene las mismas piezas:

| Componente | Qué hace | Ejemplo simple |
|---|---|---|
| Datos | Obtener precios históricos y en tiempo real | Velas diarias de una API |
| Señal | Aplicar las reglas para decidir | ¿La media de 50 está sobre la de 200? |
| Riesgo y tamaño | Calcular cuánto operar y verificar límites | Fórmula del Módulo 06 |
| Ejecución | Enviar y gestionar órdenes | Orden bracket por API |
| Registro y monitoreo | Guardar todo y avisar si algo falla | Archivo de registro y alerta por correo |

## Tipos de automatización

- **Semiautomática**: el programa analiza y te avisa; tú decides y ejecutas. Es el mejor punto de partida.
- **Automática con supervisión**: el programa ejecuta y tú revisas a diario.
- **Totalmente automática**: corre en un servidor sin intervención. Solo tiene sentido después de meses de funcionamiento supervisado.

## Calcular indicadores

Estas son las fórmulas del Módulo 04 escritas en pandas:

```python
cierre = datos["Close"]

# Rentabilidad diaria
rentabilidad = cierre.pct_change()

# Media móvil simple de 50 días y exponencial de 20
sma50 = cierre.rolling(50).mean()
ema20 = cierre.ewm(span=20, adjust=False).mean()

# ATR de 14 días con el suavizado de Wilder
cierre_ant = cierre.shift(1)
rango_verdadero = pd.concat([datos["High"] - datos["Low"],
                             (datos["High"] - cierre_ant).abs(),
                             (datos["Low"] - cierre_ant).abs()], axis=1).max(axis=1)
atr14 = rango_verdadero.ewm(alpha=1/14, adjust=False).mean()

# RSI de 14 días
cambio = cierre.diff()
ganancia = cambio.clip(lower=0).ewm(alpha=1/14, adjust=False).mean()
perdida = (-cambio.clip(upper=0)).ewm(alpha=1/14, adjust=False).mean()
rsi14 = 100 - 100 / (1 + ganancia / perdida)

# Volatilidad anualizada de 20 días
vol_anual = rentabilidad.rolling(20).std() * np.sqrt(252)

print(pd.DataFrame({"cierre": cierre, "sma50": sma50, "atr14": atr14, "rsi14": rsi14}).tail().round(2))
```

Conceptos de pandas que aparecen:

- `rolling(n)` crea una ventana móvil de n filas sobre la que se calcula una media, una desviación, etc.
- `ewm(...)` calcula promedios exponenciales. `span=20` corresponde a α = 2 ÷ 21; `alpha=1/14` es el suavizado que usó Wilder.
- `shift(1)` desplaza la serie un día hacia adelante: el valor de cada fila pasa a ser el del día anterior. Es la herramienta clave para **evitar el sesgo de anticipación**.

# lección: Un backtest completo en Python

## La estrategia

Programamos la estrategia del Módulo 08: estar comprado en SPY cuando la media de 50 días está sobre la de 200, y fuera del mercado en caso contrario, con un costo de 0,05% por cada cambio de posición.

## El código

```python
precio = datos["Close"]
rapida = precio.rolling(50).mean()
lenta = precio.rolling(200).mean()

# 1 = comprado, 0 = fuera. La señal se conoce al cierre de cada día...
senal = (rapida > lenta).astype(int)
# ...así que la posición cambia al día siguiente: evita el sesgo de anticipación
posicion = senal.shift(1).fillna(0)

rent_activo = precio.pct_change().fillna(0)
costo = 0.0005                                  # 0,05% por cambio de posición
cambios = posicion.diff().abs().fillna(0)       # 1 el día que se entra o se sale
rent_estrategia = posicion * rent_activo - cambios * costo

def metricas(r, nombre):
    capital = (1 + r).cumprod()
    anios = len(r) / 252
    cagr = capital.iloc[-1] ** (1 / anios) - 1
    vol = r.std() * np.sqrt(252)
    sharpe = r.mean() / r.std() * np.sqrt(252)
    dd_max = (capital / capital.cummax() - 1).min()
    print(f"{nombre:<18} CAGR {cagr:6.1%}   Vol {vol:5.1%}   Sharpe {sharpe:5.2f}   DD máx {dd_max:6.1%}")

metricas(rent_activo, "Comprar y mantener")
metricas(rent_estrategia, "Cruce 50/200")
print(f"Exposición: {posicion.mean():.0%}   Operaciones: {int(cambios.sum() / 2)}")
```

## Cómo funciona

- `senal` vale 1 los días en que la media rápida está sobre la lenta.
- `posicion = senal.shift(1)` hace que la posición de hoy dependa de la señal de **ayer**. Sin este desplazamiento, el backtest usaría el cierre de hoy para decidir si captura la rentabilidad de hoy: sesgo de anticipación puro.
- `posicion * rent_activo` es la rentabilidad diaria de la estrategia: la del activo cuando estás dentro y 0 cuando estás fuera.
- `cambios * costo` descuenta el costo cada día en que la posición cambia.
- `metricas` calcula las métricas del Módulo 08 a partir de las rentabilidades diarias.

Una simplificación: aquí la posición cambia al **cierre** del día siguiente a la señal. Para simular la entrada en la **apertura** habría que usar la rentabilidad desde la apertura. Con estrategias lentas como esta la diferencia es pequeña; con estrategias de pocos días es importante.

## Qué mirar en los resultados

Al ejecutarlo verás una línea para comprar y mantener y otra para la estrategia. Las preguntas que importan:

1. ¿La estrategia mejora el **drawdown máximo** frente a comprar y mantener? Ese suele ser el valor real de los filtros de tendencia.
2. ¿A cambio de cuánta rentabilidad?
3. ¿Cuántas operaciones hizo? Con menos de 20 operaciones en 25 años, cualquier conclusión es frágil.
4. ¿Qué pasa si triplicas el costo?

```python
for c in [0.0005, 0.001, 0.002]:
    metricas(posicion * rent_activo - cambios * c, f"Costo {c:.2%}")
```

Modifica el código para probar todas las combinaciones de medias rápidas (20, 30, 40, 50, 60, 70) y lentas (150, 175, 200, 225, 250), e imprime el Sharpe de cada una. ¿Cómo sabes si el resultado de 50/200 es robusto?

# lección: Simulación de Monte Carlo

## Para qué sirve

Una **simulación de Monte Carlo** repite un experimento aleatorio miles de veces para ver la distribución de resultados posibles. En trading responde preguntas como: con este sistema y este riesgo por operación, ¿qué tan grande puede ser el drawdown? ¿Qué probabilidad hay de perder la mitad de la cuenta?

## El código de las tablas del Módulo 06

```python
import numpy as np

def simular(p_acierto, ganancia_r, riesgo, operaciones=200, repeticiones=20000, semilla=7):
    gen = np.random.default_rng(semilla)
    # Matriz de verdadero/falso: cada fila es una historia de 200 operaciones
    gana = gen.random((repeticiones, operaciones)) < p_acierto
    # Cada operación multiplica el capital por (1 + riesgo × ganancia) o por (1 − riesgo)
    factores = np.where(gana, 1 + riesgo * ganancia_r, 1 - riesgo)
    capital = np.cumprod(factores, axis=1)
    # Máximo histórico en cada momento (el capital inicial es 1)
    maximos = np.maximum.accumulate(np.maximum(capital, 1), axis=1)
    dd_max = (1 - capital / maximos).max(axis=1)
    return np.median(dd_max), (dd_max >= 0.5).mean()

for riesgo in [0.005, 0.01, 0.02, 0.05, 0.10]:
    dd, p50 = simular(0.40, 2, riesgo)
    print(f"Riesgo {riesgo:5.1%}: drawdown típico {dd:5.1%}, prob. de caer 50% o más {p50:6.1%}")
```

Al ejecutarlo obtendrás cifras casi idénticas a las de la tabla del Módulo 06 (pueden variar unas décimas por el azar de la simulación).

## Monte Carlo con tus propias operaciones

Con tu diario de trading puedes hacer algo más útil: tomar tus resultados reales en R y **reordenarlos o remuestrearlos** al azar para ver qué drawdowns podrías haber tenido con las mismas operaciones en otro orden.

```python
resultados_r = np.array([2, -1, -1, 2.5, -1, -0.5, 1, -1, -1, 3])   # tu diario
gen = np.random.default_rng(1)
muestras = gen.choice(resultados_r, size=(10000, 100), replace=True)  # 100 operaciones
riesgo = 0.01
capital = np.cumprod(1 + riesgo * muestras, axis=1)
maximos = np.maximum.accumulate(np.maximum(capital, 1), axis=1)
dd = (1 - capital / maximos).max(axis=1)
print("Drawdown típico:", f"{np.median(dd):.1%}", " Peor 5%:", f"{np.quantile(dd, 0.95):.1%}")
```

El valor del «peor 5%» es una referencia mejor para planear que el drawdown de tu historial, que es solo una de las muchas secuencias posibles.

# lección: Conectar con un broker

## Cómo funciona una API de trading

Una **API** es una interfaz para que los programas hablen con el broker:

- **REST**: tu programa envía una solicitud (consultar el saldo, enviar una orden) y recibe una respuesta. Es como cargar una página web.
- **WebSocket**: una conexión abierta por la que el broker te envía precios o confirmaciones en tiempo real, sin que tengas que preguntar.

Brokers con APIs conocidas: Interactive Brokers (TWS API y Client Portal API), Alpaca (acciones de EE.UU., con cuenta de práctica gratuita), y la mayoría de exchanges de criptomonedas (la librería **ccxt** unifica más de cien).

## Ejemplo con la cuenta de práctica de Alpaca

La librería oficial `alpaca-py` permite enviar órdenes a una cuenta de práctica:

```python
# pip install alpaca-py
import os
from alpaca.trading.client import TradingClient
from alpaca.trading.requests import MarketOrderRequest, TakeProfitRequest, StopLossRequest
from alpaca.trading.enums import OrderSide, TimeInForce, OrderClass

# Las claves se leen de variables de entorno: nunca las escribas en el código
cliente = TradingClient(os.environ["ALPACA_API_KEY"], os.environ["ALPACA_SECRET_KEY"], paper=True)

cuenta = cliente.get_account()
capital = float(cuenta.equity)

# Tamaño con la fórmula del Módulo 06
entrada, stop, objetivo = 500.0, 490.0, 520.0
riesgo = capital * 0.005                       # 0,5% de la cuenta
cantidad = int(riesgo // (entrada - stop))

orden = MarketOrderRequest(
    symbol="SPY", qty=cantidad, side=OrderSide.BUY, time_in_force=TimeInForce.DAY,
    order_class=OrderClass.BRACKET,
    take_profit=TakeProfitRequest(limit_price=objetivo),
    stop_loss=StopLossRequest(stop_price=stop),
)
enviada = cliente.submit_order(orden)
print(enviada.id, enviada.status)
```

La orden **bracket** (Módulo 02) envía la entrada junto con el stop y el objetivo: si el programa se cae después de entrar, la posición sigue protegida en el broker.

## Lo que todo bot necesita además de la estrategia

1. **Registro de todo**: cada señal, orden, ejecución y error, con fecha y hora, en un archivo.
2. **Manejo de errores**: la conexión se cae, una orden se rechaza, los datos llegan tarde. El programa debe detectarlo y no repetir órdenes a ciegas.
3. **Conciliación**: comparar periódicamente las posiciones que el programa cree tener con las que el broker dice que tienes.
4. **Límites de seguridad codificados**: tamaño máximo por orden, pérdida máxima diaria, número máximo de órdenes por hora.
5. **Interruptor de apagado** (*kill switch*): una forma inmediata de cancelar todo y cerrar posiciones.

```python
# Interruptor de apagado: cancela órdenes abiertas y cierra todas las posiciones
cliente.close_all_positions(cancel_orders=True)
```

:::alerta Knight Capital (2012)
El 1 de agosto de 2012, un error en el despliegue de software de Knight Capital, uno de los mayores creadores de mercado de EE.UU., activó código antiguo que envió millones de órdenes no deseadas en 45 minutos. La empresa perdió unos 440 millones de dólares y tuvo que ser rescatada y vendida. Los controles automáticos de riesgo y un interruptor de apagado probado no son opcionales.
:::

## Seguridad de las claves

- Guarda las claves en **variables de entorno** o en un gestor de secretos, nunca en el código ni en un repositorio público.
- Usa claves con los **permisos mínimos**: sin permiso de retiro.
- Empieza siempre con `paper=True` o la cuenta de práctica, y pasa a real solo después de semanas sin errores.

# lección: Aprendizaje automático en finanzas

## Qué es

El **aprendizaje automático** (*machine learning*) son métodos que encuentran patrones en datos sin que se programen las reglas a mano: regresiones regularizadas, árboles de decisión, *random forests*, *gradient boosting* y redes neuronales. Se entrenan con datos históricos para predecir algo (por ejemplo, si la rentabilidad del próximo mes será positiva).

## Por qué es más difícil en mercados que en otros campos

| Dificultad | Qué significa |
|---|---|
| Relación señal/ruido muy baja | En una foto de un gato, el gato es claro. En los precios, la parte predecible es una fracción mínima del movimiento |
| No estacionariedad | Los patrones cambian con el tiempo; lo que funcionó entre 2010 y 2015 puede no funcionar hoy |
| Pocos datos independientes | 25 años de datos diarios son unas 6.300 observaciones muy correlacionadas, poco para modelos complejos |
| El mercado reacciona | Si un patrón se explota, desaparece |
| Fugas de información | Es muy fácil filtrar información del futuro al entrenamiento sin darse cuenta |

## Errores frecuentes

- **Validación cruzada estándar.** Mezclar al azar días del pasado y del futuro en entrenamiento y prueba filtra información, porque los días cercanos están correlacionados. Marcos López de Prado propone la **validación cruzada purgada**, que elimina del entrenamiento los datos que se solapan con el periodo de prueba.
- **Etiquetas mal definidas.** Predecir «sube o baja mañana» ignora el riesgo y el tamaño del movimiento. López de Prado propone el **método de las tres barreras**: etiquetar cada operación según toque primero un objetivo, un stop o un límite de tiempo, como en una operación real.
- **Demasiadas variables.** Con cientos de indicadores y pocos datos, el modelo aprende el ruido.

## Dónde sí ha mostrado valor

- **Combinar muchas señales débiles** de forma más flexible que una regresión lineal. Gu, Kelly y Xiu (2020) encontraron que los árboles de decisión y las redes neuronales mejoraban la predicción de rentabilidades de acciones frente a los modelos lineales, con las mayores ganancias en señales relacionadas con momentum, liquidez y volatilidad.
- **Metaetiquetado**: usar un modelo no para decidir la dirección sino para decidir **cuánto apostar** en las señales de una estrategia ya existente.
- **Datos alternativos**: procesar texto de noticias o informes de empresas.

## Una expectativa realista

Para un trader independiente, el aprendizaje automático rara vez es el punto de partida. Primero necesitas una estrategia simple con ventaja probada, datos limpios y un proceso de validación riguroso. Solo entonces un modelo puede ayudarte a filtrar o dimensionar mejor las señales. Si un modelo complejo da resultados espectaculares en un backtest, la explicación más probable es una fuga de información o sobreajuste.
